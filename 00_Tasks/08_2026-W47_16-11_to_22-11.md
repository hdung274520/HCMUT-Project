## T6. Lưu dữ liệu thô lên S3

Pi ghi dữ liệu thô khoảng **75 MB/giờ** vào `sessions/*.jsonl` và chưa xóa bao giờ. Thử nén phiên 28/10: 3,7 MB → 0,6 MB (**gzip giảm khoảng 6 lần**).

**Hướng làm (nhỏ nhất):**
- API trả về một link tải lên có thời hạn (presigned URL), để Pi không phải giữ khóa AWS
- `upload.py` nén file thô rồi tải lên **sau khi** tóm tắt phiên đã gửi thành công
- Chỉ xóa file trên Pi khi S3 đã nhận đủ

1. [ ] `template.yaml`: thêm bucket S3 (chặn truy cập công khai; tự chuyển sang lớp lưu trữ rẻ sau 30 ngày)
2. [ ] Lambda + `POST /raw-uploads`: nhận `session_id`, trả presigned PUT URL cho `raw/<session_id>.jsonl.gz`. Kiểm tra `session_id` đúng dạng `YYYYMMDD_HHMMSS` để không ghi ra ngoài thư mục `raw/`
3. [ ] Test cho Lambda mới (session_id sai dạng → 400)
4. [ ] `upload.py`: với mỗi phiên đã `sent=1` mà chưa tải thô, nén file, xin URL, PUT. Thành công thì ghi trạng thái vào `queue.db` rồi mới xóa file trên Pi. Lỗi mạng thì để lần chạy sau thử lại
5. [ ] Test cho `upload.py` (giả lập S3 trả lỗi → file trên Pi không bị xóa)
6. [ ] Deploy, rsync lên Pi, chạy với phiên của T2
7. [ ] Kiểm tra: `aws s3 ls s3://<bucket>/raw/` có file; tải về, giải nén, so số dòng với bản trên Pi

**Đạt khi:** phiên của T2 nằm trên S3 dưới dạng nén, file trên Pi chỉ bị xóa sau khi S3 đã nhận.

**Không làm tuần này:** xử lý dữ liệu thô trên AWS (chỉ lưu trữ).
