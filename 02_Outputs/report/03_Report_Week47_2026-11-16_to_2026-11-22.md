## 2. Thay đổi kiến trúc: web chính thức trên GitHub Pages

Tuần 46 có hai đường truy cập: GitHub Pages chỉ có dữ liệu mẫu, còn dữ liệu thật và trợ lý chỉ có trên EC2, khi EC2 bật. Tuần này gộp lại thành **một link duy nhất là GitHub Pages**:

```text
Muse 2 ─┐                                                    ┌──> Web dashboard (GitHub Pages, dữ liệu thật)
H303  ──┼─ BLE ─> Raspberry Pi 4 ── HTTPS ──> AWS ───────────┤        │ wss (khi EC2 bật)
YX110 ─┘          gateway.py,      (POST cần  API Gateway,   │        ▼
                  hàng đợi SQLite   API key)  Lambda,        └──> EC2 (Docker): STT → LLM → TTS
                                              DynamoDB              Tailscale Funnel
                                      GET công khai ──> Pages, trợ lý
```

*Hình 1. Kiến trúc hệ thống sau tuần 47.*

*Bảng 2. Trước và sau thay đổi*

| | Tuần 46 | Tuần 47 |
|---|---|---|
| Web có dữ liệu thật | Chỉ trên EC2, khi EC2 bật | **GitHub Pages**, luôn bật |
| API đọc dữ liệu (`GET`) | Cần API key | **Công khai**, không cần key |
| Pi gửi dữ liệu (`POST`) | API key | Giữ nguyên API key |
| Trợ lý | Web trên EC2 nối cùng host | Web trên Pages nối `wss://voice-agent.taila9efcf.ts.net/ws` |
| Khi EC2 tắt | Mất cả web lẫn trợ lý | Web vẫn có dữ liệu, chỉ ẩn nút micro |

**Điểm cần thầy cho ý kiến:** để Pages đọc được dữ liệu mà không đặt khóa bí mật trong trình duyệt, em mở các API `GET` công khai. Hệ quả là **ai có link cũng đọc được dữ liệu sức khỏe**. Em chấp nhận vì đây là dữ liệu thử của một người trong đồ án; ghi dữ liệu (`POST`) vẫn cần API key, nên không ai ghi giả được. Em đã làm thử đăng nhập bằng AWS Cognito (chỉ người đăng nhập mới đọc được dữ liệu), chạy được, nhưng gỡ ra vì đồ án không cần tính năng đăng nhập (mục 6.2).

## 4. Tổng hợp hằng đêm không bỏ sót phiên gửi muộn

**Lỗi (phát hiện khi kiểm tra mã nguồn ngày 14/11):** tác vụ lúc 00:05 chỉ tính ngày hôm qua, một lần. Nếu Pi mất mạng lúc 23:30 và gửi bù lúc 07:00, phiên đó không bao giờ được tính vào chỉ số ngày. Tình huống ở mục 3.2 có thể gây ra lỗi này nếu xảy ra gần nửa đêm.

**Sửa:** mỗi đêm tính lại **2 ngày gần nhất**. Bản ghi ngày được ghi đè theo `user_id` + `date`, nên tính lại không tạo bản trùng. Cách gọi tay cho một ngày cụ thể giữ nguyên.

**Kiểm tra:** 10 test đạt; gọi tay Lambda sau khi deploy, log ghi đúng 2 ngày được tính. Chưa kiểm tra bằng một phiên đo thật gửi muộn qua nửa đêm.

## 6. Web trên GitHub Pages và trợ lý trên EC2

### 6.1. Mở trợ lý ra Internet

- **Container tự chạy khi bật EC2** (`restart: unless-stopped`): mỗi buổi chỉ cần Start EC2, không phải SSH vào.
- **Tailscale Funnel** mở trợ lý ra Internet qua HTTPS, để trang Pages (không nằm trong mạng Tailscale) nối được. Tường lửa EC2 vẫn không mở cổng nào.
- **Chỉ nhận kết nối từ trang của đồ án:** server kiểm tra header `Origin` của WebSocket `/ws` và của `/api/config`. Danh sách cho phép gồm Pages, localhost (để thử) và chính EC2. Có test tự động; kiểm tra thật từ một trang lạ (`localhost:5501`) thì bị đóng kết nối.
- Web gọi thử `/api/config` của trợ lý (chờ tối đa 3 s) trước khi hiện nút micro. EC2 tắt thì ẩn micro và hiện "Trợ lý đang tắt".

### 6.2. Đọc dữ liệu từ Pages

Em làm thử đăng nhập bằng **AWS Cognito** (luồng authorization code + PKCE, token lưu trong `sessionStorage`), các API `GET` kiểm tra token. Bản thử chạy được: không có token thì API trả 401, đăng nhập thì web có dữ liệu thật. Sau đó em gỡ Cognito ra và mở `GET` công khai, như đã nêu ở mục 2.

Kết quả kiểm tra sau khi gỡ:

- `GET /vitals/latest` không key → **200**; `POST` không key → **403**; Pi gửi bằng key vẫn được.
- Mã nguồn web trên GitHub không còn API key, kể cả trong lịch sử git.
- Mở link Pages bằng cửa sổ ẩn danh: **ONLINE** với dữ liệu thật; hỏi trợ lý 3 câu (nhịp tim, huyết áp, SpO₂) trả lời như tuần 46; Stop EC2 thì web vẫn có dữ liệu, nút micro ẩn.

## 8. Hạn chế hiện tại

- **Dữ liệu sức khỏe đọc công khai** qua API cho bất kỳ ai có link (mục 2).
- Kiểm tra `Origin` chỉ chặn được trang web lạ trong trình duyệt; một script ngoài trình duyệt có thể giả header này và dùng trợ lý (tốn tài nguyên EC2, không đọc thêm được dữ liệu vì dữ liệu đã công khai).
- Số liệu Bảng 4 đo bằng 10 câu; từ "SpO2" vẫn bị nghe sai ở cả hai model.
- Trợ lý chỉ dùng được khi EC2 bật; cần bật trước khi demo khoảng 2 phút.
- Chưa có S3 cho dữ liệu thô; `overall_score` và phân giai đoạn giấc ngủ chưa làm; HRV chưa có số liệu đúng.
- Gateway còn lỗi traceback lúc kết thúc phiên và vẫn gửi phiên rác có nhịp tim 0 (mục 3.1).
